# فرصة — منصة وظائف

وظائف جديدة من لوحات التوظيف مباشرة، مرتّبة بدرجة مطابقة لكل مستخدم.
مشروع مستقل تماماً: قاعدة بيانات خاصة به، ولا يشترك مع أي مشروع آخر في شيء.

```
packages/engine/     العقل — تقييم وقراءة اللوحات (46 اختباراً)
apps/web/            الواجهة — React + Vite، عربية RTL
supabase/            قاعدة البيانات، العامل الدوري، الجدولة
```

---

## ما يفعله

**يقرأ من المصدر.** كل ١٥ دقيقة من Greenhouse · Lever · Ashby · Workable · SmartRecruiters.
لا إعلانات معادة: كل وظيفة تحيل إلى صاحب العمل نفسه.

**يعطي كل وظيفة درجة لكل مستخدم.** الدرجة تعتمد على مجالاته ومدنه وسنوات خبرته ومهاراته المؤكدة.
نفس الوظيفة تأخذ درجة مختلفة لشخصين مختلفين — وهذا هو بيت القصيد.

**يعطيه ورقة تعبئة.** كل ما تسأله الاستمارات — الاسم، الجوال، الجنسية، الراتب المتوقع، فترة الإشعار —
مكتوب مرة واحدة ومعه زر نسخ، إضافةً إلى إجاباته على الأسئلة المقالية المتكررة.
لا شيء في هذه الورقة مُولَّد: الفارغ يبقى فارغاً ويقول ذلك.

**يرتّب طلباته.** محفوظة ← قدّمت ← مقابلة ← عرض، مع ملاحظات وتذكير بالمتابعة بعد أسبوعين.

### قواعد لا يكسرها المحرّك

| القاعدة | لماذا |
|---|---|
| لا درجة بلا أسباب | رقم بلا تفسير لا يساعد أحداً على اتخاذ قرار |
| مهارة لم يؤكدها المستخدم = فجوة، لا رصيد | لا نفترض عن الناس ما لم يقولوه |
| الراتب يُنقل حرفياً أو يُترك فارغاً | لا تقدير ولا تخمين |
| رابط صاحب العمل يبقى كما هو | معاملات التتبع تُزال من المفتاح فقط، لا من الرابط |
| GET فقط، ولقائمة مضيفين محددة | لا يوجد في الكود مسار يرسل شيئاً لأي جهة |

## التركيب (مرة واحدة)

### ١. قاعدة البيانات

افتح مشروعك في Supabase ← **SQL Editor** ← الصق محتوى [`supabase/schema.sql`](supabase/schema.sql) ← **Run**.

ينشئ: أربعة جداول · ثماني سياسات حماية · مخزن سير ذاتية خاص · حذف حساب كامل.

> `supabase/migrations/` يحتوي نفس الشيء مقسّماً: `001_init.sql` ثم `002_apply_sheet.sql`.
> لو كانت قاعدتك فارغة فـ `schema.sql` وحده يكفي — وهو يشمل الاثنين.

> **حماية الصفوف مفعّلة على كل جدول.** المستخدم لا يقرأ ولا يكتب إلا صفوفه. الوظائف وحدها قراءة عامة — لأن إعلان الوظيفة معلومة عامة أصلاً.

### ٢. العامل الدوري

```bash
npx supabase login
npx supabase link --project-ref <معرّف-مشروعك>
npx supabase secrets set INGEST_SECRET="$(openssl rand -hex 24)"
npx supabase functions deploy ingest --no-verify-jwt
```

ثم في SQL Editor، سجّل الرابط والسر ثم شغّل [`supabase/cron.sql`](supabase/cron.sql):

```sql
select vault.create_secret('https://<project>.supabase.co/functions/v1/ingest', 'ingest_url');
select vault.create_secret('<نفس INGEST_SECRET>', 'ingest_secret');
```

> مفتاح الخدمة (`service_role`) يبقى داخل العامل فقط. المتصفح لا يراه أبداً.

### ٣. الواجهة

```bash
cp .env.example .env.local   # واملأ الرابط والمفتاح العام
npm install --prefix apps/web
npm run dev                  # http://localhost:5190
```

### ٤. النشر

الموقع منشور على Netlify: **<https://qaddim.netlify.app>**

```bash
npm run deploy      # يبني ثم يرفع عبر واجهة Netlify
```

النشر يقرأ الرمز الذي خزّنه `netlify` CLI في
`~/Library/Preferences/netlify/config.json`، فلا يحتاج تثبيتاً ولا تسجيل دخول.
والرفع بالبصمة: يُعلن عن كل ملف بـSHA1 ويُرسل ما لا تملكه Netlify فقط.

نسخة ثانية على GitHub Pages عبر `npm run deploy:pages`
(<https://sultanhad.github.io/qaddim/>). خطوة النشر عند GitHub بطيئة — تجلس
ست إلى عشر دقائق. أطلقها مرة واحدة واتركها: أي إطلاق جديد يلغي الذي قبله.

مسارات الأصول نسبية والتنقّل بالـ hash، فالموقع يعمل في جذر نطاق أو تحت مسار فرعي
بالبناء نفسه. البناء يقرأ `.env.local`؛ المفتاح العام وحده يدخل حزمة المتصفح،
ومفتاح الخدمة لا يصل إليها أبداً.

> للنشر التلقائي عند كل دفعة (بدل `npm run deploy`) تحتاج صلاحية `workflow`
> لرمز GitHub: `gh auth refresh -s workflow` مرة واحدة، ثم يمكن إضافة سير عمل
> يبني من `main`. الرابط والمفتاح العام مضافان أصلاً في **Variables** للمستودع.

وكل عنوان يُنشر عليه الموقع يجب أن يكون في Supabase → Authentication →
URL Configuration تحت **Redirect URLs**، وإلا ارتدّت روابط الدخول إلى مكان آخر.

ولربط المستودع بـNetlify ليبني تلقائياً عند كل دفعة بدل الرفع اليدوي:
`base = apps/web` · `build = npm run build` · `publish = apps/web/dist`،
مع `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` في إعدادات الموقع.

## التطوير

```bash
npm test              # 46 اختباراً: التقييم + القراءة
npm run sync:engine   # ينسخ المحرّك إلى العامل الدوري
```

المحرّك موجود في مكانين: `packages/engine/src` (الأصل) و`supabase/functions/_shared` (نسخة، لأن دوال Deno لا تستورد من خارج مجلدها).
`npm test` يفشل إذا اختلفا — فلا يمكن أن يتباعدا بصمت.

## الخصوصية

| البيانات | أين | من يصل إليها |
|---|---|---|
| الملف الشخصي | `profiles` | صاحبه فقط (RLS) |
| السيرة الذاتية | مخزن `cvs` خاص، مجلد باسم المستخدم | صاحبها فقط |
| الطلبات والملاحظات | `applications` | صاحبها فقط |
| الوظائف | `jobs` | قراءة عامة — معلومة عامة أصلاً |

**حذف الحساب فوري ونهائي:** `delete_my_account()` تمسح السيرة ثم الحساب، والباقي يسقط بالتتابع.
هذا التزام نظامي حين تحتفظ ببيانات أشخاص آخرين (PDPL)، وبُني من أول سطر لا كإضافة لاحقة.

## الحدود — اقرأها قبل أن تعد أحداً

**التقديم الآلي الكامل غير ممكن.** لوحات Workable وغيرها تضع «تحقّق أنك لست روبوتاً» (Cloudflare Turnstile)،
وهو موجود تحديداً لمنع ما نتحدث عنه. يرفض حتى النقرة اليدوية داخل متصفح مُؤتمت.
أي منصة تعد بغير ذلك إما لديها اتفاق مع أنظمة التوظيف، أو بشر يقدّمون يدوياً، أو لم تُطلق بعد.

**ما يمكن فعلاً:** فتح الاستمارة معبّأة من ملف المستخدم، فلا يبقى عليه إلا التحقق والإرسال.
الأداة التي تفعل ذلك مبنية ومختبرة في مشروع `riyadh-job-agent/local-apply`.

**التغطية محدودة بمن ينشر عبر واجهة مجانية.** مسح ٦٤ جهة سعودية أعطى ٣ مصادر صالحة فقط —
البنوك والاتصالات والجهات الحكومية كلها على Workday وSuccessFactors وTaleo، بلا واجهة عامة.
